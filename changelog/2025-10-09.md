# 2025-10-09

## Configuration System Implementation

### Summary
Implemented comprehensive NGINX-style configuration system supporting multiple servers, route-specific settings, directory listing, HTTP redirects, method restrictions, and custom error pages.

### New Classes Created

#### RouteConfig (`include/route_config.hpp`, `src/route_config.cpp`)
- Stores configuration for URL routes/locations
- Manages allowed HTTP methods per route
- Configures redirects, root directories, autoindex
- Handles CGI extension mappings
- Sets upload paths and index files

#### ServerConfig (`include/server_config.hpp`, `src/server_config.cpp`)
- Stores per-server configuration settings
- Manages host:port binding
- Defines client body size limits
- Maps status codes to custom error pages
- Contains multiple RouteConfig instances
- Implements longest-prefix matching for route resolution

#### ConfigParser (`include/config_parser.hpp`, `src/config_parser.cpp`)
- Parses NGINX-style configuration files
- Handles server {} blocks
- Parses location {} blocks within servers
- Supports comments (#) and whitespace
- Validates directive syntax
- Converts size values (K, M suffixes)

#### DirectoryListing (`include/directory_listing.hpp`, `src/directory_listing.cpp`)
- Generates HTML directory listings (autoindex)
- Reads directory contents using opendir/readdir
- Separates and sorts directories and files
- Creates styled HTML with clickable links
- Handles both files and subdirectories

### Updated Classes

#### Server
- Refactored to use ServerConfig instead of hardcoded values
- Added method-specific request handlers (GET, POST, DELETE)
- Implemented route matching and configuration application
- Added directory detection and autoindex support
- Integrated HTTP redirect functionality
- Enhanced error page handling with custom pages

#### Main
- Added config file argument support
- Instantiates ConfigParser to read configuration
- Creates Server instances from parsed configuration
- Defaults to `conf/webserv.conf`

### Configuration Features Implemented

1. **Multiple Server Blocks**: Support for multiple interface:port pairs
2. **Route/Location Configuration**: Per-route settings with longest-prefix matching
3. **HTTP Method Restrictions**: Allow/deny specific methods per route (405 response)
4. **Custom Error Pages**: Map status codes (404, 500) to HTML files
5. **Client Body Size Limits**: Parse size directives (bytes, K, M)
6. **Directory Listing (autoindex)**: Generate HTML file/directory listings
7. **HTTP Redirects**: 301 redirects using `return` directive
8. **Custom Root Directories**: Per-route root overrides
9. **Default Index Files**: Configurable index files per route
