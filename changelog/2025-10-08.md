# Changelog - 2025-10-08

## HTTP Request Handling and File Serving Implementation

### Summary
Implemented core HTTP request handling functionality with proper separation of concerns using multiple classes. The server can now parse HTTP requests, serve static files from the `www/` directory, and handle 404 errors with a custom error page.

### New Classes Created

#### HttpRequest (`include/http_request.hpp`, `src/http_request.cpp`)
- Parses raw HTTP request strings into structured data
- Extracts HTTP method, path, version, headers, and body
- Provides getter methods for accessing request components
- Handles request line and header parsing with proper error checking

#### FileReader (`include/file_reader.hpp`, `src/file_reader.cpp`)
- Manages file operations within a configured root directory (default: `www/`)
- Checks file existence using `stat()`
- Reads file contents into memory
- Determines content type based on file extension
- Supports: HTML, CSS, JS, JSON, images (JPEG, PNG, GIF), and text files

#### HttpResponse (`include/http_response.hpp`, `src/http_response.cpp`)
- Builds HTTP/1.0 compliant responses
- Sets status codes and messages (200 OK, 404 Not Found, 400 Bad Request, 500 Internal Server Error)
- Manages response headers (Content-Type, Content-Length)
- Provides factory methods for common response types (OK and 404)

#### Server (`include/server.hpp`, `src/server.cpp`)
- Orchestrates the entire request/response cycle
- Manages socket initialization, binding, and listening
- Uses non-blocking I/O with `poll()` for event-driven architecture
- Routes requests: `/` → `/index.html`, preserves other paths
- Integrates FileReader and HttpResponse to serve files
- Handles client connections and graceful shutdown

### Features Implemented

### Bug Fixes

#### Connection Reset Issue
**Problem**: Browser showed "connection reset" then "localhost did not send any data" before page finally loaded.

**Root Cause**: The server was accepting connections on non-blocking sockets but immediately trying to read from them without waiting for data to arrive. This caused premature connection handling when the client hadn't sent the request yet.

**Solution**: Added `poll()` with 5-second timeout in `handleClient()` to wait for data to be available before calling `recv()`. This ensures:
- The socket is readable before attempting to read
- No premature reads on empty sockets
- Proper synchronization between client request sending and server receiving

**Changes Made**:
- `src/server.cpp:124-142`: Added poll check before recv in handleClient()
